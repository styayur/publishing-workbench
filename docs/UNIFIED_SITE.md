# Unified site content

Workbench detects `site.manifest.json` v1 for the unified `styayur-site` format,
with `contentRoot: content`, `published: published`, `drafts: drafts` and
`private: private`. Legacy `engine.lock.json` detection remains supported.
Use a clean dedicated checkout; auto commit and push are disabled by default.
Changing the legacy profile to Unified Site preserves the target identity.

The editor supports Writing, Project, Concepts & Research, Library, About and Now.
About and Now require their singleton slugs. The publication date is explicit
YYYY-MM-DD; draft date may be blank. Updated, created and released dates never
substitute for one another. Projects support `imageAlt`, `updatedAt`, `createdAt`,
`releasedAt`, `engineeringMaturity`; concepts separately support `researchStatus`,
`researchAreas`, `references` and `relatedProjects` through Metadata JSON.

Use the existing cover field for a real local screenshot. Reliable publishing
hashes and copies it under the same draft/private/published asset boundary as the
document; promotion moves the document and copies the asset into published.
Do not label application icons as screenshots. Imported third-party images retain
their license requirements. No UI imagery is generated by this adapter.

An existing manually authored site document is protected from silent overwrite.
Use the desktop local-path import, inspect the content, then explicitly check
the site-file binding option. Binding requires the exact target file and its
unchanged import hash. The first publish journals the original bytes and attaches
the stable article marker; subsequent updates use the recorded mapping. Other
article IDs, alternate extensions and cross-status copies are rejected. Unrelated content, staged
changes, differing revisions and alternate-extension duplicates fail closed.
The site publication gate and CI remain responsible for public deployment;
Workbench never deploys an Admin/API server.

For a real private site checkout integration, set `WORKBENCH_SITE_E2E_ROOT` to a
clean committed unified-site repository and run the ignored integration test with
`cargo test --manifest-path src-tauri/Cargo.toml --test reliable unified_site_checkout -- --ignored`.
The test clones locally without hardlinks into a temporary directory, does not
push, and does not modify the supplied checkout. Its disposable baseline removes
existing About/Now only inside that temporary clone, so singleton creation can
be checked without adopting a user's manual page.
